# P0-SURF — 表层硬伤

**判据**：读者一眼看出、且没有任何辩解余地的错误。错别字、坏记号、断链接。

**默认 severity**：`minor`，但**摘要/标题/图表 caption 中的错误升为 `major`**——
那是被读得最多的地方，也是第一印象成型的地方。

**采集器**：`bin/ingest.py`（正文提取，剥离数学/verbatim/宏名）+ agent 判读

> **纪律（公理 4）**：本 tier 是自动修复的主要来源，也正因如此最危险。
> 拼写检查器会把领域术语、作者姓氏、数据集名、命令行 flag 一起"改正"。
> 所有修复必须由 agent 读上下文后逐条应用，禁止批量替换。

---

## S1. 拼写与词法

| ID | 检查项 | 备注 |
|----|--------|------|
| S1.1 | 正文英文拼写 | 必须先剥离 `$...$`、`\verb`、`lstlisting`、宏名、`\cite` key、文件路径 |
| S1.2 | 摘要与标题拼写 | 升级为 major |
| S1.3 | 图表 caption 拼写 | 升级为 major |
| S1.4 | 专有名词大小写一致 | `Transformer` / `transformer`、`GPT-5.3-codex` 全文统一 |
| S1.5 | 系统名/方法名全文统一 | 定义了 `\system{}` 宏却在某处手写成明文 |
| S1.6 | 数据集与 benchmark 名称拼写与官方一致 | `ARC-Bench` vs `ARC-BENCH` vs `\bench{}` 混用 |
| S1.7 | 英式/美式拼写统一 | `optimise`/`optimize` 不混用 |

> S1.1 真实命中：`MadGraph parton-level generatio` → `generation`。
> 这类词尾脱字是拼写检查器能抓、但人眼在通读时最容易滑过去的。
>
> S1.5/S1.6 真实命中：同一个 benchmark 在正文里以 `\bench{}`（渲染为 ARC-Bench）、
> `ARC-BENCH`、`ARC-Bench` 三种形态出现。审稿人不会因此拒稿，但会降低"这篇稿子被
> 认真检查过"的信任度。

## S2. 记号与数学

| ID | 检查项 |
|----|--------|
| S2.1 | 每个数学符号在首次出现时被定义 |
| S2.2 | 同一符号不表示两个不同的量 |
| S2.3 | 同一个量不用两个符号表示 |
| S2.4 | 上下标、粗体（向量/矩阵）约定全文一致 |
| S2.5 | 数学模式内没有该用 `\text{}` 的普通词（`$max$` → `$\max$`） |
| S2.6 | 数字与单位之间用不换行空格（`5~s` 而非 `5 s`） |
| S2.7 | 定理/引理/定义编号连续且被正确引用 |
| S2.8 | 公式中的标点（行尾逗号/句号）风格一致 |

## S3. 排版细节

| ID | 检查项 |
|----|--------|
| S3.1 | 引号方向正确（``双引号'' 而非 "双引号"） |
| S3.2 | 破折号用法：连字符 `-`、数字区间 `--`、插入语 `---` 各就各位 |
| S3.3 | 句子内引用用 `\citet`，句末用 `\citep` |
| S3.4 | `i.e.` / `e.g.` / `et al.` 后的标点与斜体风格一致 |
| S3.5 | 段首缩进与段间距没有被手工 hack 破坏 |
| S3.6 | 列表符号层级一致 |
| S3.7 | 大写标题风格（Title Case / Sentence case）全文统一 |
| S3.8 | 章节标题不以标点或悬空介词结尾 |

## S4. 结构完整性

| ID | 检查项 | severity |
|----|--------|----------|
| S4.1 | 每个被 `\input` 的文件都有实质内容 | major |
| S4.2 | 每个 `\section` 下都有正文，不只有 subsection | minor |
| S4.3 | 摘要、引言、结论都存在 | blocker |
| S4.4 | 没有编号跳号的章节 | minor |
| S4.5 | 附录中被正文 `\ref` 的每一节都存在 | major |
| S4.6 | 致谢/ethics/limitations 若被目录或正文提及则必须存在 | major |

> S4.1 + S4.6 真实命中：`sections/ethics.tex` 是 0 字节且未被 `main.tex` 引入，
> 但 `conclusion.tex` 结尾写着 "Detailed ethical issues are discussed in
> Appendix~\ref{sec:ethics}"。这条 `\ref` 会解析失败（→ B2.4 blocker），
> 而即便解析成功，读者点过去也会发现那一节是空的。
> 一条缺陷同时命中 P0-BUILD 和 P0-SURF 时，取较高 severity 并合并为一条 finding。

## S5. 语言质量（不做风格审美，只做硬伤）

| ID | 检查项 |
|----|--------|
| S5.1 | 主谓一致、时态一致 |
| S5.2 | 冠词缺失（非母语作者高频） |
| S5.3 | 句子残缺 / 悬垂修饰 |
| S5.4 | 同一段内代词指代不明 |
| S5.5 | 超长句（>60 词）且含 3 层以上从句 |

> **不在本 tier 范围**：用词是否华丽、是否使用 `state-of-the-art` 之类的营销词、
> em-dash 偏好。那些是风格选择，属于 P4-PRES，且默认不产生 finding——
> 除非它们导致 claim 被夸大（那属于 P1-CLAIM）。
>
> 这是与既有 `POLISH_REPORT.md` 做法的关键分歧：它把"禁用词表"当成主要产出，
> 结果 6 轮迭代抓了 0 个真正的缺陷。风格清洗不是审稿。
